# SHARKBRIDGE01/1 experimental dialect

This is new experimental code, not SharkLang v2.4.2 bytecode. The wire payload is canonical UTF-8 JSON using the exact Protocol canonical_json_bytes helper. The audited SharkLang strict_json_loads helper rejects duplicate keys and nonfinite constants. codec.py performs additional strict structural validation.

Keys are exactly version, q, catalog, segments, A, B, parent and leaves. The rational table contains sorted unique [signed numerator, positive denominator] pairs with gcd=1, <=512 bits per component. Every index is an actual JSON integer (not bool), nonnegative and bounded; payload size <=1,000,000 bytes, <=2,000 rational entries, <=666 catalog declarations, <=1,000 segments. Segments are sorted unique [lo-rational-ref, hi-rational-ref, catalog-ref] triples, with lo<=hi. Catalog declaration identifiers are from the explicitly constrained syntactic families; mapping them to upstream mathematics remains externally source-authenticated.

parent is [65,axis,box,[66,67]], with axis in 0..4. Each box has exactly five [lo-ref,hi-ref] coordinates. Each leaf is [node,terminal,box,anchor,rows]; this benchmark admits exactly (66,22) and (67,23), five anchor references inside the box and fifteen model rows. Direct row [0,catalog-ref]; floor row [1,floor-rational-ref,segment-ref-list] has 1..256 segments. The decoder checks both exact rational child boxes against the parent midpoint split. It does not assert a mathematical envelope inequality; that is the Lean checker's job.

LOSSLESS_ROUNDTRIP means byte-for-byte equality of canonical semantic.json after decode/encode: original rational values, all 400 segment occurrences, all 30 rows, box/anchor data, targets, catalog identities and split instruction. It is the selected mathematical checker-input stream, not a byte encoding of the complete historical JSON ledger, original Lean source, or the entire V2 binary tree. Those originals are retained separately and hash-bound; their provenance/owner metadata is not discarded or silently reconstructed by this dialect. Ordinary zlib baselines additionally verify byte-for-byte equality for semantic.json, payload.sb01 and the full original ledger.

Typed Lean tables are generated from the decoded payload. Lean decodeRow uses Option and checks every table lookup, including conversion of global catalog references to each frozen leaf's local catalog numbering. Concrete decoded_left/right theorems prove all fifteen rows equal the authentic CompactRow values, with no native evaluation. Box and anchor reconstruction equalities and decoded_children prove the geometric data. The transported acceptance theorems reuse frozen acceptance proofs: the architecture therefore retains those dependencies and does not lower total proof cost.

The JSON-byte parser, generator and cryptographic hashes are external to the Lean kernel. Lean checks typed-literal semantic correspondence; it does not authenticate payload bytes, parse canonical JSON or certify the Python codec implementation universally. No generic claim of decoder correctness for all files follows from this instance. Runtime tests alone do not prove mathematical acceptance.
