# Existing technology boundaries

All inspected originals were read only. Exact archive/member hashes are in technology_sources.json; copied excerpts remain unchanged. No original module CLI, provider, signer or network path is executed.

SharkLang: Downloads/SHARKLANG_V24_2_FINAL_REVIEW_BUNDLE_20261031.zip contains release/sharklang.py with a v2.4.2 header. Its Lexer, StaticVerifier, CompiledBytecode, VM and Lean4CertificateBackend implement the protocol DSL, index/typestate checks and generated safety certificates. OpCode has 45 members (LOAD_CONST through WITNESS_EPOCH), despite the older 44-opcode introductory prose. No MacroPiece, CompactRat or A1294 checker integration was found in this implementation. Existing float/vector and LRSC projection primitives are not a canonical arbitrary-precision rational certificate codec. This experiment reuses only the audited pure strict_json_loads and duplicate-key rejection functions by AST extraction, not the VM or the Lean backend. The proposed SHARKBRIDGE01/1 format is a new extension, not a released feature. The release bundle has no LICENSE member; no replacement license or redistribution permission is invented. Original notices remain in the private source excerpts.

Shark Protocol: the selected workspace archive contains source_v1.3.3_hardened. Its pyproject version is 1.3.3.dev0, while kernel.py retains a 1.3.2 header. These are exact identified candidate bytes, not evidence that an authenticated final v1.3.3 release was obtained. The MIT license is preserved. Existing canonical_json_bytes and sha256_canonical are pure deterministic helpers and are reused unchanged by AST extraction. The inspected implementation also defines signed ledger, head, evidence-root and manifest verification components; their full security properties are not reverified here. This experiment does not create signatures, access keys, instantiate signers, claim compatibility with the complete VRK ledger schema, or defeat rollback without a separately trusted external anchor. A locally recomputable hash manifest binds bytes only; it neither establishes author identity nor proves mathematics. The existing strict manifest verifier is inspected but not run over a released checkout.

LRSC: local v1.2.1 source bundle includes the independent numerical verifier and proof clarification supplement. Its verifier explicitly says numerical cross-check, not proof. The separate K11 exact-integer certificate defines a finite M=99 threshold benchmark with interval-derived integer bounds; its checker validates output scores/counts without repeating all 13.4 billion subsets. Neither the published-release identity nor all original LRSC proof obligations are newly authenticated in this offline task. No exhaustive LRSC computation was run. Exact interning is conventional data compression; it is not evidence that LRSC supplied a new theorem here. An explicit reflection/template residual trial is separately labelled inspired, reconstructs every row index exactly, and loses against ordinary row interning. K11 projection is excluded from authoritative data: an 11-dimensional projection of arbitrary 99-dimensional data is not injective without full residual information.

The reference directory is evidence, not a claim that the entire technologies or their generated Lean assertions were independently kernel audited in SHARKBRIDGE-01. No license, original source or release was modified. No provider API, private key or credential was accessed.
